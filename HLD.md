# HLD — Единое приложение KayFit + FitKeep

## 1. Обзор системы

Объединение двух продуктов — **KayFit** (нутрициология, подсчёт калорий) и **FitKeep** (тренировки, подбор программ) — в единое мобильное приложение с общим бэкендом, единой базой пользователей, единой подпиской и единым AI-чатом.

---

## 2. Текущее состояние (AS-IS)

```
┌─────────────────────────────┐     ┌─────────────────────────────┐
│        KayFit               │     │        FitKeep              │
│                             │     │                             │
│  KayFitMobile (Flutter)     │     │  FitKeepMobile (Flutter)    │
│  └─► carbcounter.online     │     │  └─► api.fitkeep.online     │
│       (Calories backend)    │     │       (FitnesBot backend)   │
│       SQLite/PostgreSQL     │     │       PostgreSQL            │
│       Отдельная БД юзеров   │     │       Отдельная БД юзеров   │

Проблема: два отдельных продукта, два аккаунта, две подписки,
          два чата, нет синергии между данными питания и тренировок
```

## 8. Онбординг — перечень вопросов

### 8.1 Общие вопросы (нужны обоим модулям)
| # | Вопрос | Используется в |
|---|--------|----------------|
| 1 | Имя пользователя | Auth, профиль |
| 2 | Пол (male/female) | Nutrition goals + Training matching |
| 3 | Дата рождения / Возраст | КБЖУ расчёт + Training matching |
| 4 | Рост (см) | КБЖУ расчёт |
| 5 | Текущий вес (кг) | КБЖУ расчёт + Training |
| 6 | Цель (похудение / поддержание / набор массы) | Nutrition goals + Training type |

### 8.2 Вопросы для Nutrition (KayFit)
| # | Вопрос | Используется в |
|---|--------|----------------|
| 7 | Целевой вес (кг) | Расчёт дефицита/профицита калорий |
| 8 | Уровень физической активности (1–5) | Расчёт TDEE |
| 9 | Ограничения в питании / аллергии | AI нутрициолог, рекомендации |

### 8.3 Вопросы для Training (FitKeep)
| # | Вопрос | Используется в |
|---|--------|----------------|
| 10 | Текущий % жира | Подбор программы тренировок |
| 11 | Целевой % жира | Подбор программы + план |
| 12 | Опыт тренировок (новичок / средний / продвинутый) | Training sample matching |
| 13 | Предпочтительная длительность тренировки (мин) | Расписание |
| 14 | Травмы / ограничения | Подбор упражнений (исключения) |
| 15 | Тип тренировок (сила / кардио / смешанный) | Training type matching |

### 8.4 Пост-онбординг (отдельные экраны)
| Экран | Данные | Используется в |
|-------|--------|----------------|
| Equipment Screen | Доступное оборудование | Подбор упражнений |
| Body Form Screen | Параметры тела (детально) | AI программа |
| Way to Goal Screen | Визуализация плана | Мотивация |

## 9. Стратегия миграции

```
Этап 1: Backend (приоритет)
  ├── Создать единый auth сервис с единой БД пользователей
  ├── Объединить API endpoints (prefix /api/v1/)
  ├── Создать chat router
  └── Единая система подписки

Этап 2: Мобильное приложение
  ├── Новый unified app (отдельный Flutter проект или merge)
  ├── Единый ApiClient → unified backend
  ├── Объединить навигацию (новый router.dart)
  ├── Перенести модули Workout + Nutrition
  ├── Создать Unified Chat Screen
  └── Account Screen

Этап 3: Онбординг и полировка
  ├── Единый онбординг квиз
  ├── Unified Dashboard (пользователь делает сам)
  └── Дизайн-полировка
```

## 10. Нефункциональные требования

| Параметр | Требование |
|----------|-----------|
| Auth | JWT access (15 мин) + refresh (30 дней) |
| API Latency | < 500ms для основных запросов |
| Chat Latency | < 3s для AI ответа |
| DB | PostgreSQL (единая), connection pool min=50 max=100 |
| Security | HTTPS, CORS, rate limiting на auth endpoints |
| Backward compat | Старые мобильные клиенты должны получить migration notice |
