Что точно работает и покрыто тестами
-------------------------------------------------
Структура проекта — слои роутер/сервис/репозиторий/пул настроены, dependency injection работает, конфигурация через .env.
Авторизация — регистрация, логин, рефреш токена, логаут, удаление аккаунта, AI consent, FCM токен. Unit и API тесты проходят.
Таблицы БД — users, refresh_tokens, nutrition_profiles, training_profiles, subscriptions, plans, chat_messages, quiz_answers, meal_logs, foods, nutrition_goals, equipment, translations, food_nutrients_cache и другие. Миграции 001-004 idempotent, применяются чисто.
Chat — два отдельных ассистента: тренировочный и нутрициологический. Каждый получает контекст из БД — активная программа, результаты тренировок, съеденное за день, цели по КБЖУ. История хранится отдельно по agent_type.
Nutrition API — дневник питания (добавить, редактировать, удалить), поиск продуктов, штрихкод, цели по КБЖУ, статистика за период. Все поля микронутриентов и витаминов добавлены в meal_logs и foods.
Распознавание еды — три метода: из текста, из фото (Claude Vision), из голоса (OpenAI Whisper). Обогащение нутриентами через локальный кеш и Claude с web_search. 32 unit-теста.
Training API — программы, расписание, результаты упражнений, альтернативы, максимальные веса, генерация программ.
Equipment — каталог категорий и позиций, выбор снаряжения пользователя.
Quiz/онбординг — сохранение ответов (текст, кнопки), запрос консультации.
Профиль пользователя — полный профиль, недельный прогресс, расчёт даты достижения цели по весу.
Подписки + YooKassa — список планов, создание платежа, активация, отмена, landing bid. Вебхуки с idempotency через processed_webhook_events.
Переводы — таблица translations в БД, JOIN в репозиториях тренировок и снаряжения. Скрипт импорта 260 упражнений с RU и EN переводами написан.
Unit-тестов итого: 174, все проходят.

Реализовано, но нужно проверить на проде
-------------------------------------------------
Импорт упражнений (scripts/import_exercises.py) — скрипт проверен на данных FitnesBot, dry-run прошёл чисто. Против реальной БД не запускали. Нужно прогнать и убедиться что IDs не конфликтуют с существующими записями в workout_exercises.
YooKassa вебхуки — логика обработки есть, idempotency реализована. End-to-end тест с реальным YooKassa sandbox не проводился.
FCM push-уведомления — Firebase Admin SDK инициализируется если есть credentials-файл, код отправки написан. На реальных устройствах iOS/Android не тестировали.
Расчёт КБЖУ норм — формулы покрыты unit-тестами. На реальных пользователях с разными профилями не проверяли, могут быть граничные случаи.
Middleware проверки подписки — отдельного middleware нет. Проверка статуса подписки есть в сервисе, но на уровне роутеров ограничений не выставлено. Нужно определить какие эндпоинты закрывать и добавить FastAPI dependency.
